# Веб-платформа управління музичними колекціями та їх аналізу

## Мета

Платформа призначена для ведення музичних колекцій, оцінювання треків за окремими критеріями та аналізу музичних уподобань користувача.

## Основні функції продукту

- додавання треків, альбомів та виконавців до особистої колекції;
- перегляд інформації про власні треки, альбоми та виконавців;
- оцінювання треків за окремими критеріями;
- автоматичний розрахунок середнього бала треку;
- формування рейтингів альбомів і виконавців;
- створення персональних колекцій;
- перегляд статистики музичних оцінок.

## Сценарії прототипу першого семестру

1. Користувач додає трек до своєї колекції вручну, вказуючи назву, виконавця та альбом.
2. Користувач переглядає інформацію про вже додані ним треки, альбоми та виконавців.
3. Користувач виставляє оцінки треку за критеріями від 1,0 до 10,0 з кроком 0,1.
4. Для інструментального треку користувач може вимкнути критерії «Виконання» та «Зміст». Середній бал рахується лише за активними критеріями.
5. Користувач переглядає список своїх оцінених треків, сортує його за рейтингом і бачить базову статистику.

У прототипі дані вносяться вручну одним користувачем, без інтеграції із зовнішнім API та без перегляду колекцій інших користувачів.

## Функції, відкладені на наступний семестр

- повноцінна реєстрація користувачів і керування профілями;
- отримання музичних даних через зовнішні API;
- обмін публічними колекціями та додавання друзів;
- розширена статистика у вигляді графіків;
- адміністративні функції.

## Функції поза межами продукту

- відтворення музики та зберігання аудіофайлів;
- окремий мобільний застосунок;
- платіжна система;
- текстовий чат.

## Технологічний стек

- Frontend: React, Vite
- Backend: Node.js, Express
- База даних: PostgreSQL, Prisma
- Тестування: Jest
- DevOps: Git, GitHub Issues, Milestones, Projects, Pull Requests, Docker

## Робочий процес

Для планування завдань використовується Kanban-дошка GitHub Projects.
Для роботи з гілками використовується GitHub Flow.
Правила роботи з гілками описані у файлі [docs/branching_strategy.md](docs/branching_strategy.md).

## Запуск проєкту

Детальні команди запуску бази даних через Docker Compose будуть додані після виконання практичної роботи 3.
